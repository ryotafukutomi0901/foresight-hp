# Hero Bible

> Heroはブランドの顔であり、他セクションとは別冊で管理する。
> 数値は各Bibleを参照し、ここではHero固有の決定のみを述べる。

## Hero Philosophy

> **HeroはOpeningの終着点であり、Visionへの橋渡しとなる独立した舞台である。**

Heroは「ページの先頭」ではなく **映画の第2幕の頭**。Loadingで目の中に入った視線が、まだ完全には像を結んでいない状態から始まる。

### Heroに課す2つの規律（CEO指示・厳守）

**1. 借りない**
What We Can Do 以降で使う **Narrative Corridor および車両ストーリー素材を一切使わない。**
理由: Heroで車両を見せてしまうと、What We Can Do の「発見」が死ぬ。**物語の順序はブランド体験の骨格であり、先出しは体験全体を毀損する。**

**2. 専用に作る**
Hero固有のビジュアルシステムを持つ。Openingの「目に入る」運動を受け止め、Visionの「霧が晴れる」へ渡せる**中間状態**であること。

### Heroが担う3つの機能

| | |
|---|---|
| Openingからの受け | GSAP Flip の着地点。Loadingの最終フレームがそのままHeroの初期状態になる |
| 独自の舞台 | Hero専用ビジュアル(回廊とテクスチャを共有しない) |
| Visionへの渡し | 「まだ視界が定まらない」状態を作り、Visionの起点にする |

## Hero 実装技術の選定

**結論: SVG + CSS + Canvas2D。Three.jsは使わない。**

### 3軸評価

| 技術 | ブランド体験 | 保守性 | パフォーマンス | 判定 |
|---|---|---|---|---|
| **Three.js** | ◎ 本物の奥行き | △ シーン管理が重い | **✕ 2つ目のWebGLコンテキスト** | **却下** |
| **SVG** | ○ 線の精度が高い。ロゴと同じ言語 | ◎ DOMなので状態が読める | ◎ 軽い | **採用** |
| **Canvas2D** | ○ 粒子・ディザに向く | ○ | ○ 軽い | **採用(補助)** |
| **CSS** | ○ | ◎ | ◎ | **採用(補助)** |
| **Shader単体** | ◎ | ✕ WebGL前提なのでThree.jsと同じ問題 | ✕ | 却下 |

### なぜThree.jsを却下したか

1. **LCPを直撃する。** Heroはファーストビュー。ここでWebGLの初期化とテクスチャ確保が走ると、最も測定される指標が悪化する
2. **WebGLコンテキストが2つになる。** Vision以降で本格的な3D空間が動く。Heroで別コンテキストを起こすとGPUメモリを二重に消費する。**これは既に自己申告済みの設計負債(`VisionScene` と `Atmosphere` の2重起動)と同じ過ちを、意図的に繰り返すことになる**
3. **必要な絵に対して過剰。** Heroで表現するのは「まだ像を結ばない視界」であり、**奥行きよりも"にじみ"と"粒"** が主題。これはSVGフィルタとCanvas2Dで十分に、かつ高品質に作れる

> Three.jsを使うこと自体を目的にしない、というCharterの指示に対する直接の回答。
> 詳細は [decision-log.md](./decision-log.md) に記録。

## Hero Layout

```
┌────────────────────────────────────────────────────────┐
│  [logo]                    BUY  SELL  FIND  CONTACT   │ ← 固定ヘッダー
├────────────────────────────────────────────────────────┤
│                                                        │
│                                                        │
│    EVERY CAR HAS A NEXT.            ╱                 │
│                                    ╱  ← Silent Gaze   │
│    車の未来を、                   ╱     (SVGの視線)    │
│    見通す。                      ╱                    │
│                                                        │
│    どんな状態の車にも、                                │
│    次の可能性がある。                                  │
│                                                        │
│    [ 車を売る → ]  [ 車を探す → ]                      │
│                                                        │
│                      SCROLL                            │
│                        │                               │
└────────────────────────────────────────────────────────┘
      ← 左50%: 文字        右50%: 空白と視線 →
```

- **左に文字、右は空ける。** ファーストビューの50%以上を空ける([Art Bible](./art-bible.md#negative-space))
- 車両は置かない(規律1)
- 右の空白には **Silent Gaze = 一本の光の線**のみ

## Hero Typography

| 要素 | スケール | 備考 |
|---|---|---|
| 英文リード | `label` | `EVERY CAR HAS A NEXT.` トラッキング `0.42em` |
| 主見出し | `display-xl` | 2行。`車の未来を、` / `見通す。` |
| 補助 | `body-l` | 2行 |
| CTA | `body-l` | 主+副の2つ。同じ強さにしない |

**主見出しは行マスクで下から立ち上げる。** 文字単位の3D回転(`charsRise`)はここでは使わない — Heroは第一印象であり、**技巧が先に見えてはいけない**。技巧は What We Can Do 以降で使う。

## Hero Motion

Loadingの完了信号(`onOpeningDone`)を待って再生する。**マウント時に即再生しない**(雲の下で演出が終わってしまうため)。

| 順 | 対象 | 動き | ease |
|---|---|---|---|
| 1 | Silent Gaze(線) | 中央から左右へ伸びる | `inOut` |
| 2 | 英文リード | `trackIn`(字間0.5em→0.42em) | `out` |
| 3 | 主見出し | 行マスク `yPercent 110→0` | `out` |
| 4 | 補助 | `layerIn` | `out` |
| 5 | CTA | `layerIn` stagger | `out` |
| 6 | SCROLL | fade | `linear` |

数値は [Motion Bible](./motion-bible.md)。

**常時動くもの**: Silent Gaze の線が**極めてゆっくり明滅**する(周期6秒・振幅0.06)。これだけで「停止しているが生きている」状態になる。

## Hero Camera

**3Dを使わないためカメラは存在しない。** 代わりに**ポインタ追従のパララックス**で視差を作る。

| 層 | 移動量 | lerp |
|---|---|---|
| Silent Gaze | `±12px` | `0.08` |
| 主見出し | `±4px` | `0.08` |
| 背景の粒 | `±20px` | `0.05` |

`lerp` は [Camera Bible](./camera-bible.md) の `lerp.pointer` に揃える。**Heroだけ違う追従感にしない。**

## Hero Lighting

背景 `#090909`。光源はSilent Gazeの線のみ。

- 線の周囲に `radial-gradient` で微かなにじみ
- フィルムグレインは**全画面共通のものを使う**(Heroだけ別のグレインにしない)
- ビネットは [Lighting Bible](./lighting-bible.md) と同値

## Hero Transition

### Loadingからの受け（GSAP Flip）

Loadingの最終フレームで画面中央にあるロゴが、**Flipでヘッダー左上のロゴ位置へ変形移動する。**

```
Loading最終フレーム            Hero初期状態
  ロゴ（中央・大）      →      ロゴ（ヘッダー左上・小）
  瞳の残光（中央）      →      Silent Gaze の線（右半分）
```

`duration: 1.0` / `ease: out`。**この1本のFlipが「Loadingは別物ではなくページの一部だった」と理解させる。**

### Visionへの渡し

Heroを下へ抜けるとき、Silent Gaze の線が **右へ収束して消える**。
Visionは「霧の中から視界が開く」セクションなので、Heroは**視界が閉じた状態で終わる**。閉じてから開く順序を守る。

## Hero Scroll Behavior

- **pinしない。** Heroは滞在ではなく通過点。pinすると「進めない」ストレスになる
- スクロール開始と同時にパララックスで層が分離し、Visionへ繋がる
- SCROLLキューはスクロール開始で即座に消す

## Hero Accessibility

| 項目 | 対応 |
|---|---|
| 見出し | `<h1>` はHeroに1つだけ |
| Silent Gaze | `aria-hidden`(装飾) |
| CTA | キーボードで到達可。フォーカスリング2px + offset 3px |
| reduced-motion | アニメーションを再生せず**最終状態を即適用**。線の明滅も止める |
| コントラスト | `#F2F2F2` / `#090909` = 17.4:1 |
| ポインタ追従 | reduced-motion時は無効 |

## Hero Performance Rule

**Heroはサイト全体で最も厳しい予算を持つ。** ファーストビューだから。

| 項目 | 予算 |
|---|---|
| WebGLコンテキスト | **0** |
| 追加JSバンドル | **10KB以下**(gzip) |
| 画像 | **ロゴSVGのみ**(ラスター画像を使わない) |
| LCP要素 | 主見出しのテキスト |
| DOM数 | 60以下 |

詳細は [performance-budget.md](./performance-budget.md)。

## Heroが満たすべき受け入れ条件

- [ ] 回廊画像・車両ストーリー素材が**1枚も描画されていない**
- [ ] **WebGLコンテキストを生成していない**
- [ ] Loadingのロゴが Flip でヘッダーへ移動し、継ぎ目が見えない
- [ ] Visionへ入る前に Silent Gaze が消えている(閉じてから開く)
- [ ] reduced-motion で全内容が静止状態で読める
- [ ] `<h1>` が1つだけ存在する
