# Performance Budget

> **実装前に決める。** 出来上がってから測ると「もう直せない」になる。
> 演出よりも体験品質を優先する。予算を超えたら**演出を削る**。

## サイト全体

| 指標 | 予算 | 測定条件 |
|---|---|---|
| **LCP** | ≤ 2.5s | モバイル4G相当。**Openingスキップ時のHero**で判定 |
| **CLS** | ≤ 0.05 | 全区間 |
| **INP** | ≤ 200ms | CTA・フォーム操作 |
| **FPS(desktop)** | ≥ 55 | スクロール中の平均 |
| **FPS(mobile)** | ≥ 40 | 同上。全デバイス同一体験のため機能は削らず品質で調整 |
| **JS初期容量** | ≤ 250KB (gzip) | three.js を含まない初期チャンク |
| **総転送量** | ≤ 1.2MB | 初回訪問・Opening込み |

**LCPをHeroで判定する理由**: Openingは初回のみ・スキップ可能で、常時発生するコストではない。ここを含めると数値が実態と乖離する。

## 3D(WebGL)

| 指標 | 予算 | 備考 |
|---|---|---|
| **WebGLコンテキスト数** | **1** | 現状2つ走っている(`VisionScene` + `Atmosphere`)。**Phase 6で統合する** |
| **Draw Calls** | ≤ 80 | 霧26 + 塵1 + 光条3 + 回廊10 + ポストプロセス |
| **GPU Memory** | ≤ 180MB | |
| **Texture合計** | ≤ 24MB | VRAM上 |
| **1テクスチャ最大** | 2048×2048 | これを超えるものは分割か縮小 |
| **dpr上限** | 2 | 高DPR端末で内部解像度が跳ねるのを防ぐ |

## セクション別

| セクション | 特記 |
|---|---|
| **Loading** | 総転送 ≤ 500KB。5.0秒で完結 |
| **Hero** | **WebGLコンテキスト 0** / 追加JS ≤ 10KB / **ラスター画像 0**(ロゴSVGのみ) / DOM ≤ 60 |
| **Vision** | 変更しない(現状維持) |
| **What We Can Do** | 回廊10枚。1枚 ≤ 250KB(AVIF) |
| **Buy / Sell / Find** | **3Dを停止**。GPU負荷を実質ゼロにする |
| **CTA** | 3D再開。軽量構成 |

**LIGHT区間で3Dを止めるのは、表現上の判断だが性能上の利得も大きい。** ページ後半でGPUを解放できるため、フォーム操作のINPが安定する。

## 予算超過時の削減順序

演出から削る。**情報とアクセシビリティは最後まで削らない。**

```
1. ポストプロセス（色収差 → Bloom → DOF の順に外す）
2. 霧・塵の枚数
3. 回廊の同時表示枚数
4. パララックスの層数
─────────── ここから先は要CEO判断 ───────────
5. セクションの演出そのもの
6. 情報量
```

## 計測方法

- Playwright + CDP で `Performance.getMetrics` / fps サンプリング
- Lighthouse(モバイル)
- `chrome://tracing` でGPUメモリ
- **Phase 7 で実測し、超過分をこの順序で削る**
