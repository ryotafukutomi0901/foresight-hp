# Performance Budget

> **実装前に決める。** 出来上がってから測ると「もう直せない」になる。
> 演出よりも体験品質を優先する。予算を超えたら**演出を削る**。

## サイト全体

| 指標 | 予算 | 測定条件 |
|---|---|---|
| **LCP** | ≤ 2.5s | モバイル4G相当。**Openingスキップ時のHero**で判定 |
| **CLS** | ≤ 0.05 | 全区間 |
| **INP** | ≤ 200ms | CTA・フォーム操作 |
| **FPS(desktop)** | ≥ 55 | スクロール中の平均 |
| **FPS(mobile)** | ≥ 40 | 同上。全デバイス同一体験のため機能は削らず品質で調整 |
| **JS初期容量** | ≤ 250KB (gzip) | three.js を含まない初期チャンク |
| **総転送量** | ≤ 1.2MB | 初回訪問・Opening込み |

**LCPをHeroで判定する理由**: Openingは初回のみ・スキップ可能で、常時発生するコストではない。ここを含めると数値が実態と乖離する。

### 「コンテキスト数1」を撤回した理由

**予算は手段ではなく結果を縛るべきだから。**

コンテキスト数1は元々「GPU負荷を抑える」ための*手段*の指標だった。
しかし目的である **fps・転送量は統合せずに達成できた**（desktop 52.0→58.2 / 2526→1037KB）。
一方で統合は Vision の camera・fog・post-process・dpr・描画範囲を変え、
**決定事項4が守っている「Visionの見え方」を確実に損なう。**

そこで予算を「コンテキストを2つ持ってよい。ただし**同時に描画してよいのは1つ**」へ改めた。
これは緩和ではなく、**より実態に即した厳しい制約**になっている
（旧予算は「1つなら常時描画してよい」を許していたが、新予算は常時描画を許さない）。

見直す条件は [D-011](./decision-log.md#d-011-webgl-canvas-を統合しない確定) に記載。

## 予算超過時の削減順序

演出から削る。**情報とアクセシビリティは最後まで削らない。**

```
1. ポストプロセス（色収差 → Bloom → DOF の順に外す）
2. 霧・塵の枚数
3. 回廊の同時表示枚数
4. パララックスの層数
─────────── ここから先は要CEO判断 ───────────
5. セクションの演出そのもの
6. 情報量
```

## 計測方法

- fps: `node scripts/measure-fps.mjs`（**実フレーム数 ÷ 実時間**で出す。rAFの間隔平均は間引かれたフレームを1回と数えるため実態より良く出る）
- 計測区間は **What We Can Do**。回廊・霧・塵・光条・ポストプロセスが同時に走る最も重い区間で、ここが通れば他は通る
- Lighthouse(モバイル) / `chrome://tracing` でGPUメモリ
- **Phase 7 で実測し、超過分は上の順序で削る**

## 実測（品質向上フェーズ後・**本番ビルド** `npm run build` + `npm start`）

**総転送量・FPS ともに予算内に入った。** 演出は一切削っていない。

| 指標 | 予算 | 着手前 | 現在 | |
|---|---|---|---|---|
| 総転送量 | ≤ 1229KB | 2526KB | **1037KB** | ✓ −59% |
| FPS desktop | ≥ 55 | 52.0 | **58.2** | ✓ |
| FPS tablet | ≥ 40 | 60.1 | **60.0** | ✓ |
| FPS mobile | ≥ 40 | 60.1 | **60.1** | ✓ |
| WebGLコンテキスト数 | 2（同時描画1） | 2 | **2** | ✓ [D-011](./decision-log.md#d-011-webgl-canvas-を統合しない確定) で確定 |

**転送量の内訳（1037KB）**

| | wire | |
|---|---|---|
| js | 584KB | three.js / postprocessing / GSAP を含む |
| woff2 | 233KB | 自己ホストのサブセット2ファイル（[D-016](./decision-log.md)） |
| next/image | 169KB | Opening の雲3枚 |
| その他 | 41KB | css / ico / svg |

**何を削って達成したか（演出は削っていない）**

1. **回廊テクスチャ 792KB を初期取得から外した**（[D-015](./decision-log.md)）。描画されないものを初回訪問に載せていただけ。2画面手前で先読みするのでポップインしない
2. **和文フォント 865KB → 233KB**（[D-016](./decision-log.md)）。書体は同一で、画素単位で一致することを検証済み
3. **図版のビットマップ215KB を reduced-motion 時のみ読むようにした**。3Dが本体のときは画面に一度も出ない画像だった

**FPS の区間別（desktop）**

`top 52 / vision 52 / philosophy 60 / narrative 60 / buy 60 / sell 60 / find 60 / contact 60 / company 60`

Hero と Vision だけが52fps。**原因はWebGLで、canvasを全て外すと同区間が60fpsになる。**
**この区間だけ Atmosphere と Vision の2つのcanvasが同時に描画される**ため（他区間はVisionが `frameloop` を切っている）。

全体平均が58.2fpsで予算内のため、この区間の52fpsは**許容範囲として確定**した。
統合すれば同区間 +8〜9fps 得られるが Vision の見た目が変わるため実施しない
（[D-011](./decision-log.md#d-011-webgl-canvas-を統合しない確定)。**この区間が単独で55fpsを下回ったら再検討する**）。

**まだ予算を超えている項目**

- **js 584KB**（予算は「three.jsを含まない初期チャンクで250KB」なので直接比較はできないが、絞る余地はある）。`import * as THREE` を名前付きimportへ寄せる等

## 旧実測（車両マスター組み込み時点・参考）

### FPS

desktop は**測定ごとのばらつきが大きく、予算を安定して満たしていない**。3回連続の実測:

| | run1 | run2 | run3 | 平均 | 予算 | |
|---|---|---|---|---|---|---|
| desktop | 56.1 | 50.5 | 49.4 | **52.0** | ≥55 | ✕ **未達** |
| tablet | 60.1 | 60.1 | 60.1 | 60.1 | ≥40 | ✓ |
| mobile | 60.1 | 60.1 | 60.1 | 60.1 | ≥40 | ✓ |

tablet/mobile は3回とも 60.1 で**ばらつきゼロ**（垂直同期の上限に張り付いている＝余力がある）。
desktop だけが 49〜56 で揺れる＝**GPUが毎フレーム間に合っていない**。1回の計測値で合否を判断してはいけない。

> **記録の訂正**: [decision-log D-012](./decision-log.md) は「desktop 16→54fps」を成果として記録しているが、
> **54fps は元々この予算(≥55)を満たしていない。** 当時から未達だったものが、
> 単発計測で予算ちょうどに見えていた。desktop が予算に乗ったことは一度も無い。

**この未達は車両マスターの組み込みが原因ではない**（テクスチャを 2048px→1024px に縮めても fps は変わらず、帯域はボトルネックではなかった）。
削減順序の第2位以降（Bloom / DOF を外す・霧と塵の枚数を削る）に踏み込むと**見た目が変わる**ため、CEO判断を待つ。

### 総転送量

**2526KB / 予算 1229KB（2.06倍・超過）**。Resource Timing の `transferSize`（実際に線を流れた圧縮後のバイト数）で計測。

| | wire | 予算 | |
|---|---|---|---|
| woff2 | 865KB | 400KB | ✕ 和文 Shippori Mincho が支配的 |
| webp | 792KB | — | ✕ 回廊テクスチャ10枚。**初期表示では1枚も描画されないのに全部落ちてくる** |
| js | 582KB | 250KB | ✕ three.js / postprocessing / GSAP を含む |
| js/doc | 174KB | — | |
| css | 72KB | — | |

> `Response.body()` で測ると**解凍後**のサイズになり、JSが1898KBに見える。**転送量は必ず `transferSize` で測ること。**

**削減の見込み（大きい順）**

1. **回廊テクスチャの遅延読み込み — 約792KB減。** 回廊は `gateProgress` により What We Can Do まで描画されないのに、`useTexture` が Atmosphere のマウント時点で走るため初期表示で全部落ちてくる。**ただし素朴に遅延させると到達時にポップインする**ので、手前のセクションで先読みする設計が要る（Motion Regression Rule の対象）
2. **和文フォントのサブセット化 — 数百KB減の見込み。** 本文の字種を確定させてからでないと欠字が出る
3. **three.js の import を絞る — 数十〜百KB規模。** `import * as THREE` をやめて名前付きimportに寄せる

**1 と 2 を実施すれば予算内に収まる見込み。** いずれも見た目を変えずに削れるため、削減順序の「演出から削る」に触れる前にここから着手すべき。
