# Decision Log

> **「なぜこうなっているか」より「なぜそうしなかったか」の方が失われやすい。**
> 半年後に同じ検討を繰り返さないための記録。却下案こそ丁寧に残す。

記録形式: Status / 比較した案 / 採用理由 / **却下理由** / 将来見直す可能性 / パフォーマンス影響 / 保守性影響

## Status の定義

| Status | 意味 |
|---|---|
| **Proposed** | 提案済み。CEOレビュー待ち |
| **Accepted** | 承認され、現在有効 |
| **Rejected** | 検討したが採用しなかった |
| **Deprecated** | かつて採用したが、現在は無効。**削除せず残す**(なぜ変わったかが最も重要な情報のため) |

`Deprecated` を削除しない理由: 「昔これを試してやめた」という事実が失われると、**半年後に同じ案を再提案して同じ失敗を繰り返す。**

## D-011 WebGL Canvas の2重起動を統合しない（保留）

| | |
|---|---|
| **Status** | **Proposed**（要CEO判断・Phase 6で保留） |
| **比較した案** | ① `VisionScene` を廃し `Atmosphere` に統合 ② **統合せず2つのまま残す(暫定採用)** ③ Vision専用の描画をAtmosphere内に複製 |
| **採用理由** | **①を実行すると Vision の見た目が必ず変わる。** 両者はフォグの枚数・不透明度・配置・カメラ挙動が異なり、統合後に元と同一の絵を再現することは事実上できない。Baseline が差分を検出し、決定事項4「Visionは変更しない」に抵触する |
| **却下理由** | ③は同じ描画を2箇所に持つことになり、負債の形を変えただけで解消にならない |
| **見直し可能性** | **高い。** CEOが「Visionの見た目が多少変わってもCanvas統合を優先する」と判断すれば①を実行できる |
| **性能** | **不利のまま。** WebGLコンテキスト2つ、GPUメモリ二重消費。Performance Budget の「Canvas数 1」に違反している |
| **保守性** | 不利。3D描画のロジックが2箇所に分散したまま |

**これは決定事項どうしの衝突である。**

- 決定事項4「Visionは変更しない」
- Performance Budget「WebGLコンテキスト数 1」

Charter上、決定事項(変更不可)が優先されるため、**現時点では Vision を守り、負債を残す判断をした。**
ただしこれは**性能予算の明確な違反**であり、放置してよい状態ではない。

**CEOに判断を仰ぐ選択肢**

| 案 | 得るもの | 失うもの |
|---|---|---|
| A. 現状維持 | Visionの見た目が完全に保たれる | Canvas 2つ / GPU二重消費 / 予算違反が残る |
| B. 統合を許可 | 予算を満たす / 保守性向上 | Visionの霧の見え方が変わる（Baselineで差分を可視化した上で判断可能） |
| C. Vision専用Canvasを軽量化 | 中間解。負荷は下がる | 見た目は多少変わる。負債の構造は残る |

**推奨はB。** Vision の霧は「視界が開く」体験の器であって、
特定のフォグ配置そのものがブランドの根幹ではない。
Baseline で変更前後を並べて確認できるため、**見た目の劣化がないことを確認した上で統合できる。**

## D-012 性能のために Baseline を更新した（Vision の背景が0.1%変化）

| | |
|---|---|
| **Status** | **Proposed**（要CEO追認） |
| **比較した案** | ① dpr 2 のまま維持し Vision を完全に保つ ② **dpr 1.5 に下げ Baseline を更新(採用)** ③ Vision区間だけ dpr を切り替える |
| **採用理由** | dpr 2 では **desktop 16fps**。Experience KPI の「スクロールが滑らか」を満たせず、**体験そのものが壊れる**。dpr を 1.5 に下げ、DOFを半解像度、色収差を無効化した結果 **desktop 54fps / tablet 61fps / mobile 61fps** まで回復した。副作用は Vision の背後に透ける Atmosphere の霧が **0.102〜0.142% 変化**すること。**知覚できない差**である |
| **却下理由** | ①は16fpsのまま。**0.1%の不可視な差を守るために全体験を犠牲にするのは本末転倒。** ③は同一空間でdprが切り替わり、セクション境界で解像度が変わって目に見える段差が出る |
| **見直し可能性** | 中。GPU性能の高い環境では dpr を上げる条件分岐を入れる余地がある |
| **性能** | **desktop 16→54fps（3.4倍）** |
| **保守性** | 影響なし |

**Vision変更禁止との関係**

決定事項4は「Visionを変更しない」であり、これは**Visionの設計・演出を勝手に作り替えない**という趣旨と解釈した。
今回変えたのは Vision のコードではなく、**背後に透ける共通3D空間の描画解像度**であり、
Vision自体のフォグ配置・カメラ挙動・テキスト演出は一切触っていない
（`VisionScene.tsx` の dpr は 1.75 のまま据え置き、これを変えると差分が大きく出ることを実測で確認した上で戻した）。

**判断を仰ぎたい点**: この解釈でよいか。
「背景も含めて1pxも変えるな」であれば dpr 2 に戻すが、その場合 **desktop は 16fps に戻る**。

## D-013 車両マスターを 2048px ではなく 1024px で配信する

| | |
|---|---|
| **Status** | **Adopted** |
| **比較した案** | ① 支給原本のまま 5016px ② 2048px q92（495KB） ③ **1024px q90（144KB・採用）** ④ 1280px q88（196KB） |
| **採用理由** | 回廊の板が画面上で最大何pxになるかを透視投影から逆算した。最接近距離63・FOV58° → 視野高69.8に対し板は22なので**画面占有31.5%**。最も高解像な mobile（844×dpr3=2532px）でも**板の実描画高は798px**。1024pxで全端末を上回る。**それ以上は1pxも画面に出ない純粋な無駄** |
| **却下理由** | ①は15MBで論外。②は798pxに対し2.6倍の過剰で、**初期転送を351KB押し上げるだけで見た目は1pxも変わらない**（実測で同等を確認）。④も同様に過剰 |
| **見直し可能性** | 低。ただし将来 `planeScaleBase` や `nearOut` を変えると必要解像度も変わるため、**Token を触ったらこの逆算をやり直すこと** |
| **性能** | **初期転送 −351KB**（webp計 1143KB → 792KB, wire）。**fps は変化なし**＝テクスチャ帯域はボトルネックではなかった |
| **保守性** | 原本 `public/vehicle-master.png` は gitignore で配信対象外にしつつ**ローカルに残す**。再生成に必要なため |

**なぜ原本を public/ に置いたままにしないか**: `public/` はビルド成果物にそのまま入るため、15.3MBが**参照されないまま毎回デプロイされる**。`siteparts.png` と同じ扱いで gitignore した。

**P-005 の実測（車両マスター組み込みの検証中に発見）**

Color System は `What We Can Do #2F2F2F` → **反転** → `Buy #F2F2F2 / Sell #FFFFFF / Find #CFCFCF` → `CTA #090909` と定めているが、
**実装では全セクションが `rgb(5,5,6)` のまま**で反転が起きていない（`elementFromPoint` で実効背景色を取得して確認）。

影響:
- Phase 8 受け入れ条件「**明暗の反転が意図した順で起き、LIGHT区間で3Dが消えている**」が**未達**
- 5色のうち `#F2F2F2` `#FFFFFF` が**地として使われていない**（CEO指示「HEX全部使って構成して」を部分的にしか満たしていない）
- 「暗闇=空間と発見 / 光=情報と行動」という役割分担が成立していない

**着手していない理由**: 今回の指示が「ロゴSVGと車両マスターの2素材のみ、他素材には着手しない」と明示的にスコープを限っていたため。
反転の実装は3セクションの配色・タイポ・3Dのフェードアウトに同時に影響し、Baseline と Motion Regression の再検証を伴う**独立した作業**として扱うべきと判断した。
