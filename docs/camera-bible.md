# Camera Bible

> **カメラ数値の唯一の出典。** 値は `lib/tokens.ts` の `camera` に反映する。
> 初期値は既存実装 `components/three/Atmosphere.tsx` の実測値を起点にしている。

## 原則

1. **カメラは常に「奥へ入っていく」。** 引かない。Foresight = 見通す、に対して視点が対象の内側へ入る動きが正しい。Openingの「目に入る」から最後まで、この方向を反転させない。
2. **カメラそのものを直接書き換えない。** `useThree()` が返すカメラは共有オブジェクトで、React Compiler の immutability 規則にも触れる。**シーン側の `group` を動かす**。`FogExp2` は距離で効くため見え方は等価。
3. **場当たりで数値を決めない。** セクションごとに FOV を変えたくなったら、まず「本当に必要か」を疑う。画角が変わると空間の同一性が壊れる。

## Distance（Z方向の設計）

| トークン | 値 | 意味 |
|---|---|---|
| `corridor.gap` | `16` | 1枚あたりの奥行き間隔 |
| `corridor.leadIn` | `128` | 進行度0での1枚目の距離。`farOut` より奥に置く |
| `corridor.travel` | `210` | 進行度0→1で回廊が手前へ流れる距離 |
| `corridor.nearOut` | `-57` | **これより手前には来させない(厳守)。** 下記の検算による |
| `corridor.nearIn` | `-38` | 完全に消えきる位置 |
| `corridor.farIn` | `-95` | ここまで来たら完全に見える |
| `corridor.farOut` | `-125` | これより奥は見えない |
| `fog.zRange` | `-22 〜 -132` | 霧の配置範囲。手前に大きな板を置くと画面が白く潰れる |

### `nearOut` の検算（拡大率1.6倍上限の実装値）

透視投影では **見かけの大きさ ∝ 1/カメラからの距離**。したがって

```
拡大率 = (カメラ〜farIn の距離) ÷ (カメラ〜nearOut の距離)
```

カメラ z = `6` なので、拡大率を上限 `1.6` に収めるには

```
(6 − farIn) / (6 − nearOut) ≤ 1.6
(6 − (−95)) / (6 − nearOut) ≤ 1.6
101 / (6 − nearOut) ≤ 1.6
6 − nearOut ≥ 63.1
nearOut ≤ −57.1
```

→ **`nearOut = -57`**(実測 `101 / 63 = 1.60`)

> 当初 `-48` としていたが、これは `101 / 54 = 1.87倍` となり上限を超えていた。
> **「寄りすぎない」は感覚で決めず、透視投影の式から逆算する。**

`nearOut` と `scale.corridorMax`(Motion Bible)は**同じ制約を別軸から表現したもの**。両方を守る。

### 不透明度の3段カーブ

**遠景は薄く / 中景でピーク / 近景は素早く落とす。**

| トークン | 値 | 意味 |
|---|---|---|
| `corridor.opacityFar` | `0.5` | 遠景の上限。**大気遠近で奥ほど薄く霞ませる** |
| `corridor.opacityPeak` | `1.0` | 中景のピーク |
| `corridor.nearFalloffPower` | `1.6` | 近景の落ち方。1より大きいほど急速に消える |

```
opacity = farVis × nearVis^1.6 × level
  farVis  : farOut→farIn で 0→1
  nearVis : nearOut→nearIn で 1→0
  level   : 中景でのみ opacityPeak まで持ち上がる重み（既定は opacityFar）
```

**なぜ遠景を 1.0 にしないか**: 全ての板が等しく濃いと「奥行きのある空間」ではなく「板が並んでいる」に見える。
奥を薄く霞ませることで初めて距離が知覚される。フォグだけでは加算合成の素材に効きが足りない。

**なぜ近景を急速に落とすか**: `nearOut` で唐突に消えると「板が消えた」と気づかれる。
手前ほど視野に占める面積が大きいため、線形に落とすと消える瞬間が目立つ。`^1.6` で先に薄くしておく。

## Speed / Follow / Lerp

| トークン | 値 | 用途 |
|---|---|---|
| `speed.page` | `40` | ページ全体の進行で霧が奥へ退く量 |
| `speed.dust` | `60` | 塵の移動量。霧より速くして相対視差を作る |
| `lerp.camera` | `0.05` | カメラ追従の減衰。粘りを出す |
| `lerp.mesh` | `0.1` | 個別メッシュの向き追従 |
| `lerp.pointer` | `0.08` | ポインタ追従のパララックス |

**lerpを使う理由**: スクロール値を直に代入すると、スクロールが止まった瞬間に画面も止まる。減衰を挟むと「重量のあるカメラが遅れて追いつく」感覚になり、これが没入の主要因になる。

## DOF（被写界深度）

| トークン | 値 |
|---|---|
| `dof.focusDistance` | `0.022` |
| `dof.focalLength` | `0.08` |
| `dof.bokehScale` | `3.2` |

手前の1枚にピントが合い、奥がボケる状態を作る。**これが「平面の集合」を「空間」に見せる最大の要因。**
初期値は `0.012 / 0.05 / 5` だったが、被写体までボケて主題が読めなかったため実測で締めた。

## Parallax

| トークン | 値 |
|---|---|
| `parallax.narrow` | `viewport幅 / 1280` でクランプ(上限1.0) |
| `parallax.backOff` | `(1 - narrow) * 6` |

画面が狭いほど被写体が寄って見えるため、空間ごと後ろへ下げる。**機能は削らず寸法だけ合わせる**方針(全デバイス同一体験)の実装。

## LIGHT区間の扱い

背景が明転する Buy / Sell / Find では **3Dをフェードアウトさせる**。
加算合成のため明部では白い線画が背景に溶けて消えるので、描画し続ける意味がない。
→ カメラは停止させず**進行だけ継続**させ、再び暗転する CTA で自然に戻れるようにする。
